# Contributing to System-Design

First off, thank you for considering contributing to System-Design. It's people like you that make System-Design such a great tool.

## How to Contribute

### Reporting Bugs

If you find a bug, please create a GitHub issue outlining:
- The expected behavior
- The actual behavior
- Steps to reproduce
- Specifications like your OS and MATLAB/Simulink version

### Suggesting Enhancements

If you have an idea for a new feature or improvement:
- Open an issue describing the feature.
- Explain why this enhancement would be useful to most users.
- Outline the proposed implementation if you have one.

### Pull Requests

1. Fork the repository and create your branch from `main`.
2. If you've added code that should be tested, add tests.
3. Ensure the test suite passes.
4. Make sure your code adheres to standard conventions and IEEE mathematical documentation styles.
5. Issue that pull request!

## Code Style

- MATLAB: Follow standard camelCase naming conventions. Use clear, self-documenting variable names.
- Simulink: Ensure all blocks are labeled clearly. Group complex subsystems.
- C++ / PlatformIO: Adhere to standard embedded C++ practices. Use clang-format if possible.
- Documentation: Ensure all technical documents strictly avoid the use of emojis and maintain a professional tone.
